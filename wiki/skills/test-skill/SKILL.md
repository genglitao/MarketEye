# Test 测试技能

本技能负责**按设计文档进行验收测试**，是被sdlc-skill调用的环节技能之一。

## 触发条件

- sdlc-skill 评估后认为需要验收测试
- coding-skill 完成后需要验证功能

## 前置条件

| 场景 | 前置依赖 |
|------|----------|
| 功能验收 | 需求文档(PRD) + 设计文档(SDD) |
| 纯技术变更验收 | 设计文档(SDD) |

## 工作流程

### 步骤1：读取输入

1. 读取 PRD 和 SDD 文档，理解功能需求和预期行为。
2. 读取 PROTO 文件（如存在）。PROTO 是用户确认后的正式交付物，具有约束力。

### 步骤2：判断测试模式

1. 查找旧版 TC：同模块同功能、上一版本号的 TC 文档。
2. **存在旧版 TC → 增量测试模式**：
   - 读取 SDD §10 任务清单，提取本次变更任务（变更类型非 `新增` 的任务对应修改已有用例，`新增` 对应新增用例）
   - 旧版 TC 中未受影响的用例原样保留
3. **不存在旧版 TC → 全新测试模式**：按步骤 3 完整生成。

**回归测试判断**：生成 TC 前，对照 [文档规范](../../rules/doc-rules.md) §5.3 第 5 章中定义的强制触发条件（公共组件修改 / schema 变更 / 依赖升级 / 框架升级），判断本次是否需要回归测试。满足任一条件时，TC §5 必须包含回归验证点，不可跳过。

### 步骤3：生成测试用例

按 [文档规范](../../rules/doc-rules.md) §5.3 生成 TC，按 §3 输出到对应目录。

**每条功能测试用例须包含 `关联任务` 字段**，对应 SDD §10 任务编号（T001...），无对应时填 `—`。

**增量测试模式**：在旧版 TC 基础上，仅生成/修改本次变更任务对应的用例，其余不变。

TC 产出后，**必须**按 [文档规范](../../rules/doc-rules.md) §9 同步更新 [wiki.md](../../wiki.md)，在"业务文档"下按模块+功能定位到对应标题，追加 `- [TC-xxx](相对路径) — 一句话摘要`。

**覆盖率检查**：TC 生成后、执行前，统计覆盖率并记录在 TC §1.3：
- **需求覆盖率**：TC §3 功能测试用例覆盖 PRD §3.2 每个功能点的比例（已覆盖数/功能点总数）
- **API 覆盖率**：TC §2 接口测试用例覆盖 SDD §3.2 每个接口的比例（已覆盖数/接口总数）
未达 100% 的项须补充用例，无法覆盖的须在 TC §1.3 中说明原因。

### 步骤4：准备测试环境

- 启动被测服务
- 准备测试数据：
  - 数据准备脚本（`TC-DATA-prep`）和清理脚本（`TC-DATA-cleanup`）存放在 TC 同目录 `scripts/` 下
  - 每轮测试前重置测试数据至已知状态，避免上轮残留数据影响本轮结果
- **界面自动化环境**（涉及窗口交互测试时需准备）：
  - Python 环境已装 `Pillow`（仅测试用，程序本体不得依赖）
  - 测试脚本必须先 `SetProcessDpiAwareness(2)` 声明 DPI 感知，否则 `GetWindowRect` 返回逻辑坐标、截图为物理像素，两者不匹配会导致裁剪错位
  - 窗口位置固定到屏幕内（如 `+300+120`），避免落在屏幕外导致截图出现黑边
  - 交互可通过**直接调用事件处理方法**模拟（如构造事件对象调用 `on_press` / `on_drag` / `on_release`），比 `SendInput` 更稳定可重复

**执行前检查**：开始执行测试前，检查 TC §1.6 测试执行配置是否完整：

| 配置项 | 来源 |
| --- | --- |
| 启动方式 | `pythonw ticker.pyw`（或 `启动盯盘.bat`） |
| 使用的配置文件 | 测试用 `config.json`（须备份原文件，测试后还原） |
| 窗口初始位置与尺寸 | 测试脚本指定 |
| 操作区域坐标 | 从 SDD §3.5 获取（含 `px()` 换算后的物理像素） |

任一需用户提供的字段为空时，暂停执行，提醒用户补充后再继续。

### 步骤5：执行验收测试

**增量测试模式**：仅执行本次变更相关的用例，未受影响用例可跳过。

按 TC 逐项验证，先执行接口测试再执行功能测试，功能测试内按优先级 P0 → P1 → P2 执行：

**外部接口测试**（优先执行，作为功能测试准入条件）：
- 执行 TC 同目录 `scripts/` 下的接口测试脚本，验证行情/搜索接口的请求与解析是否符合 SDD 定义
- 覆盖正常返回、字段缺失、编码异常（GBK/UTF-8）、空结果、超时与断网
- 校验解析后的价格、涨跌幅、名称字段与接口原始报文一致（注意腾讯接口按 `~` 分隔、价格字段需除以 100 等换算规则）
- 接口测试全部通过后方可进入功能测试。如接口测试存在失败项，应修复后重新执行接口测试，不得跳过进入功能测试

**功能测试**：
- 按优先级 P0 → P1 → P2 顺序执行，P0 全部通过后方可进入 P1
- 验证每个功能点是否符合需求
- 验证用户交互流程是否顺畅
- 验证边界条件和异常处理
- **界面交互验证**（涉及窗口操作时执行）：
  - 按 TC 中定义的界面交互测试用例，用 `scripts/TC-UI-*.py` 脚本驱动程序执行操作步骤（调用事件处理方法或 `SendInput`）
  - 每步操作后按 `GetWindowRect` 的物理像素坐标截图，将 TC 中定义的每步预期结果与截图像素比对验证（颜色取样、元素位置、黑块检测）
  - **截图强制要求**：每步操作必须保存截图至 TC 同目录 `screenshots/` 下，命名为 `{用例编号}-step{N}-{timestamp}-{random}.png`（如 `TC-F-01-step1-20260522143025-1.png`）。**各用例执行完毕后，必须在本轮通过项表中逐条标注截图路径。缺一条则该用例视为未完成。**
  - 判定标准示例：缩放后近黑像素占比应为 0、四角应透出桌面、列坐标应随窗口宽度线性变化
  - 全部步骤通过即用例通过，失败则记录失败步骤和页面快照

### 步骤6：更新测试报告

**每轮测试（含缺陷验证）结束后，立即更新 TC §6，更新完成前不得向用户汇报测试结果。**

- §6.1 测试执行结果：追加本轮执行记录（轮次、日期、用例数、通过/失败/阻塞数、需求覆盖率、API 覆盖率），并填写对应的通过项/失败项/阻塞项明细
- §6.2 缺陷跟踪：记录新发现的缺陷，更新已有缺陷状态

支持多轮执行：每轮测试重复步骤4→5→6，结果逐轮追加到 TC §6，不创建新版本文档。

### 步骤7：询问并生成 SOP 操作手册

本轮测试执行完毕且无失败项后，主动询问："是否需要生成 SOP 操作手册？"

- **需要**：读取 TC 界面交互测试用例和 `screenshots/` 下所有截图，按 [文档规范](../../rules/doc-rules.md) §5.5 生成 `SOP-盯盘君-{功能名}-v{x}.{y}.{z}.md`，输出到 `docs/操作手册/{功能名}/v{x}.{y}.{z}/`。**screenshots 目录中有对应截图的步骤必须引用，缺一条则 SOP 视为未完成。** 内容生成规则：
  1. 从 TC 操作步骤转为用户引导式描述，每步引用 `screenshots/` 下截图
  2. 从 SDD 或运行环境获取环境信息（Windows 版本、Python 版本、网络可达性）
  3. 根据 TC 边界测试和异常场景归纳常见问题（FAQ），提供原因和解决方案
  4. 从 PRD/SDD 中提取专业缩写和内部名词，整理术语表（附录）
- **不需要**：跳过本步骤，继续执行后续步骤

SOP 产出后，**必须**按 [文档规范](../../rules/doc-rules.md) §9 同步更新 [wiki.md](../../wiki.md)，在"业务文档"下按模块+功能定位到对应标题，追加 `- [SOP-xxx](相对路径) — 一句话摘要`。

测试流程全部结束后，主动询问："是否需要清理测试数据？"

- **需要**：执行 `scripts/` 下的数据清理脚本（`TC-DATA-cleanup`），删除本次测试产生的数据
- **不需要**：保留测试数据，供后续排查或复测使用

**测试全部通过后，输出以下提醒**：

> 功能测试已通过。功能发布至生产环境后，请通知更新版本状态为"已发布"，AI 将批量更新该版本所有文档（PRD/SDD/TC/PROTO/SOP）的头部状态字段及变更记录。

### 步骤8：更新版本状态（用户触发）

当用户确认功能已发布至生产环境后（如"xxx功能已发布"），执行以下操作：

1. 将该版本所有文档头部的"版本状态"从"未发布"改为"已发布"
2. 在每份文档变更记录的该行变更内容中追加"已发布"标记

### 步骤9：独立审核

启动**独立的 Agent 实例**，依据 [doc-rules](../../rules/doc-rules.md) §5.3 对产出的 TC 文档进行合规性审核。如生成了 SOP，同时依据 §5.5 和 §6.6 审核 SOP。审核通过后流程结束，等待用户指示下一步。产生文档的 AI 不得自行审核。

## 注意事项

- 严格按照SDD文档验收，不做额外测试
- 发现问题及时记录并反馈
- 验收通过后更新TC状态
- 界面交互测试用例必须用 `scripts/TC-UI-*.py` 脚本自动化执行；操作步骤与 TC 一一对应，每步结果与预期一一对应
- SOP 有截图未引用视为未完成；可从任何轮次截图取用
- 非交互类用例（纯接口验证、解析逻辑校验）可手动执行；但涉及缩放、拖动、滚动、折叠、右键菜单等功能点的用例必须通过脚本自动化验证
- 测试脚本会改写 `config.json` / `position.json`，**执行前必须备份、执行后必须还原**，避免污染用户真实配置
