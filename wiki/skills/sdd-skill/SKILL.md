# SDD 技术设计技能

本技能负责**详细技术设计与SDD文档生产**，是被sdlc-skill调用的环节技能之一。

## 触发条件

- sdlc-skill 评估后认为需要技术设计
- prd-skill 完成后需要生成技术方案

## 前置条件

| 条件 | 说明 |
|------|------|
| 需求文档(PRD) | 必须有PRD才能进行技术设计 |
| 例外 | 纯技术框架设计不需要PRD |

## 工作流程

### 步骤1：读取输入

1. 读取对应的 PRD 文档，理解需求背景和功能要求。
2. 读取 PROTO 文件（如存在）。PROTO 是用户确认后的正式交付物，具有约束力。

### 步骤2：判断设计模式

1. 查找旧版 SDD：同模块同功能、上一版本号的 SDD 文档。
2. **存在旧版 SDD → 增量设计模式**：
   - 读取旧版 SDD，理解现有设计
   - 提取 PRD §1.2 变更记录中当前版本行的 `变更类型` 和 `关联章节`
   - 将 PRD 关联章节映射到 SDD 对应章节，锁定本次需要调整的设计范围
   - 未出现在关联章节中的 SDD 内容，原样保留不做改动
3. **不存在旧版 SDD → 全新设计模式**：按步骤 3 完整设计。

### 步骤3：技术方案设计

**增量设计模式**（存在旧版 SDD）：
- 以旧版 SDD 为基底，仅调整步骤 2 锁定的受影响章节
- 技术选型、架构设计等全局章节如未受影响则不动
- 变更内容与 PRD §1.2 变更记录的 `变更类型` 对应：`新增` 对应新增设计章节、`修改` 对应修改已有章节、`删除` 对应删除或标记废弃

**全新设计模式**（无旧版 SDD）：按 [文档规范](../rules/doc-rules.md) 完整设计。

设计内容包括：

**技术范围确认**：
- Python 版本与标准库模块（禁止第三方依赖）
- 配置存储方案（`config.json` / `position.json` 的字段约定）
- 外部接口（腾讯行情、标的搜索）与 Win32 API 依赖

**架构设计**：
- 分层职责划分（窗口绘制 / 行情获取 / 配置持久化 / 交互）
- 类与方法结构、调用关系
- 数据流设计（请求 → 解析 → 内存模型 → 绘制）

**数据模型设计**：
- 配置结构定义（`config.json` 的键、类型、默认值、是否可缺省）
- 内存态与配置态的映射关系
- 向后兼容规则（旧配置缺字段时的兜底）

**外部接口设计**：
- 接口地址与请求方式
- 返回报文结构与字段索引（`~` 分隔的位置、编码 GBK/UTF-8）
- 异常处理（超时、字段缺失、空结果、乱码）

**界面设计**：
- 如存在 PROTO，引用 PROTO 文件路径，不再重复描述布局和交互，仅补充技术层面内容：画布元素与绘制函数映射、状态变量（折叠/滚动/缩放中）、坐标与 `px()` 换算
- 如无 PROTO，按 doc-rules.md §5.2 完整描述：窗口布局、交互流程、视觉状态（配色/字体/圆角，取值见 ui-rules.md）

### 步骤4：产出SDD文档

按 [文档规范](../rules/doc-rules.md) §3 输出 SDD 文档。

任务清单（第 10 章）生成规则：

- **增量设计模式**：仅列出本次受影响的变更任务，与 §1.2 变更记录和 §4 代码位置对齐
- **全新设计模式**：从完整设计生成全部任务，按设计章节顺序编排

### 步骤5：更新 wiki.md 索引

SDD 产出后，**必须**按 [文档规范](../rules/doc-rules.md) §9 同步更新 [wiki.md](../wiki.md)：

1. **系统级/模块级 SDD** → 更新"全局"区域，追加 `- [SDD-xxx](相对路径) — 一句话摘要`
2. **功能级 SDD** → 在"业务文档"下按模块+功能定位到对应 H3/H4 标题，追加 `- [SDD-xxx](相对路径) — 一句话摘要`；无对应标题则新增

### 步骤6：独立审核

启动**独立的 Agent 实例**，依据 [doc-rules](../rules/doc-rules.md) §5.2、§6.3 和 §7 对产出的 SDD 文档进行合规性审核。审核通过后流程结束，等待用户指示下一步。产生 SDD 的 AI 不得自行审核。

## 注意事项

- 技术方案应贴合现有架构风格
- 如发现需求问题，通知sdlc-skill回退到需求环节
- 涉及数据库变更时，需明确迁移方案
