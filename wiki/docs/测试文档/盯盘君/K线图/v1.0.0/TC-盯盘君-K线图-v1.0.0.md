### 1.4 测试方法

- **接口层**：真实网络 + 白盒交叉验证。真实请求腾讯三个接口，将报文解析结果与 `fetch_kline`/`fetch_minute` 返回逐字段比对；异常路径（空结果、非法报文、超时、断网）用桩替换 `urlopen`。
- **界面层**：自动化黑盒为主、白盒断言为辅。`importlib` 加载 `ticker.pyw`，桩替换 `fetch_quotes`/`fetch_kline`/`fetch_minute`/`is_trading` 使数据可编程控制；交互经 `event_generate` 走真实事件绑定链（滚轮、按下/拖动/松开、双击、移动）；画布 item 属性（text/fill/coords）直接读取 + 截图按窗口物理像素实拍取色双重验证。
- **截图方式**：本机会话桌面不做窗口合成，`ImageGrab` 全屏只能拿到壁纸（首轮 147 张截图全部无效，已废弃重拍）。改用 Win32 `PrintWindow(PW_RENDERFULLCONTENT)` + `GetDIBits` 直接取窗口客户区位图，与画布坐标一一对应（`uikit.grab_hwnd`）。
- **双击类交互**：Tk 不允许合成 `<Double-Button-1>`，且 `event_generate` 的事件时间戳若相同/不可比会把相邻两次 press 误判为双击。故双击一律直调真实处理函数（`app.on_double` / `reset_view`），必须合成时事件时间取 `GetTickCount()` 基值每次 +600ms。
- **真网用例**：AC-08（复权三档）、AC-32/33（分时）、AC-35（120 分）、AC-36（MACD 手算）使用真实行情数据，保证数值口径可信。
- **隔离**：全部写盘重定向到 `scripts/_tc_config.json` / `_tc_position.json` 沙箱（Harness 重定向 `CONFIG_FILE`/`POS_FILE`）；`TC-DATA-prep` 备份真实配置并记录 md5，`TC-DATA-cleanup` 比对还原。（本轮前序事故教训：测试覆盖真实 config.json 导致自选丢失，故本册隔离为强制前提。）
- **执行顺序**：接口（TC-API）→ 功能（TC-F-01~38，脚本内按依赖连续执行，P0 先于 P1）→ 回归（TC-R-01~04）。AC-19 交易时段实时刷新于收盘后执行，采用白盒注入报价路径验证，口径在用例内注明。
