### 1.4 测试方法

- **接口层**：白盒 + 真实网络。真实请求腾讯行情接口，再独立请求一次取原始报文，逐字段比对解析结果；异常路径用桩替换 `urlopen`（断网、空结果、字段不足、价格为 0）。
- **界面层**：自动化黑盒。以 `importlib` 加载被测 `ticker.pyw`，用桩替换 `fetch_quotes` / `is_trading` / `_prepare_industry`，使行情可编程控制；事件经 `event_generate` 注入真实坐标，走真实事件绑定链（双击折叠、拖动、右键菜单）。
- **断言方式**：三重交叉验证 —— ① 画布 item 的 `text` / `fill` / `coords` 直接读取；② `PIL.ImageGrab` 按窗口矩形实拍后按色取样，确认文字确实绘制到屏幕（排除「item 存在但被遮挡」）；③ 计时链句柄与真实换条时刻（`time.time()`）插桩测量。
- **隔离**：测试全程只写 `scripts/_tc_config.json` / `_tc_position.json` 沙箱，被测程序的 `CONFIG_FILE` / `POS_FILE` 在 Harness 构造时重定向；`TC-DATA-prep` 备份真实配置，`TC-DATA-cleanup` 逐字节比对后还原并清理沙箱（本轮记录：`config.json` 未被改动；`position.json` 因窗口被移到测试坐标而改动，已自动还原）。
- **执行顺序**：接口 → 功能用例（按 TC-F-01~TC-F-12 编号连续）→ 非功能 → 回归 → 自检用例。接口先行是 doc-rules §5.3 的准入要求；功能用例按编号连续跑而非按 P0/P1 分批，因全部用例共用同一套桩环境、分批只增加启动开销不增加证据强度（P0 与 P1 的划分见 §1.3 与各用例属性表）；自检用例读取真实配置，故排在最后。
