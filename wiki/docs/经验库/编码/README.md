## 顶层窗口的 <Configure> 拿不到子控件的新尺寸（2026-10-30）

**问题**：拖动改变 K 线窗口大小后，三图（主图/量/MACD）比例按**上一帧**尺寸绘制，
要等下一次行情刷新（≤3 秒）才自动纠正；测试里表现为副图降级阈值恒不触发。

**根因**：`<Configure>` 只绑在 `Toplevel` 上。WM_SIZE → Tk 派发顶层 Configure 时，
pack/grid 还没重排子控件，此刻 `canvas.winfo_height()` 仍是旧值（实测请求
960×510、画布已变 450，事件里读到 900）。用旧值算布局 → 永远慢一帧；画布自身的
Configure 无人处理，也就没人补这一帧。

**做法**：把 `<Configure>` 同时绑到**画布**，布局 + 重绘只在画布事件里做
（`e.widget is self.cv`）；顶层事件只负责「尺寸落盘 + 300ms 防抖」。绘制入口保留
`_sync_layout()` 对账（画布实际尺寸 ≠ 缓存 W/H 就先重算），覆盖「数据先于最终
Configure 到达」的时序。

**效果**：缩放后首帧即正确；副图降级用例（<60 逻辑像素）稳定通过；首开裁切缺陷
（BUG-01）的兜底仍在。

**适用场景**：任何「窗口尺寸驱动布局」的 Tk 应用，尤其是多子图/多分区画布。

## 分类建议

本项目为单模块程序，经验不按前后端分层，按主题命名文件即可（如 `win32-句柄类型声明.md`、`缩放与圆角冲突.md`、`滚动条被遮挡.md`）。常见主题：

- 窗口绘制与几何（Canvas、圆角、DPI、缩放）
- 行情获取与解析（接口编码、字段索引、异常降级）
- 交互（鼠标事件、热区判定、拖动状态机）
- 配置与持久化（JSON 读写、向后兼容、位置钳制）
